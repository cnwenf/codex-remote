# 任务通知与连接状态分离验收 — 2026-09-09

## 当前状态

0.5.34 已于北京时间 2026-09-09 16:05 正式公开发布，正式资产和安卓更新地址复核完成。用户在知晓原生页面未复验后明确要求“直接发版”；Mac 锁屏后的 Android / iPhone 页面点击仍记为未验收，不绕过锁屏，不把发布等同于全部原生验收通过。

本轮只处理任务通知的展示与状态归属。红米真机私网请求超时根因仍缺设备证据，图片发送问题按用户要求延期；不宣称这两项已解决。既有 Mac Gateway 0.5.32 保持运行，没有重启 Desktop 或替换本机网关。

## 最终交互约定

- 聊天连接正常就显示绿色，包括任务通知延迟、失败或通知权限关闭的情况。
- 对话页和连接列表移除任务通知大块警告及重试按钮；通知只影响设置页，不驱动连接颜色。
- 连接中 / 重连中为灰色空心点，实际离线为红色 ×；原生横竖屏使用同一标识。连接胶囊仍打开该连接的会话列表。
- 设置页使用“任务通知”和“重新检查”，展示对应连接、真实最近成功时间、连续失败次数和可识别的失败原因。
- 点击重新检查不代表检查成功；原生真实成功后才更新成功时间、清空失败。说明仅检查最近打开的连接，通知受 Android 系统设置影响。

## 代码与反例

- 沿用现有设置组件和原生服务，不新增全局健康状态模型或共享状态框架。删掉原来的对话通知插槽及无用布局规则。
- 通知事实写入和连接切换由同一个原生同步边界保护，写入前校验连接 ID 与地址。实际 HTTP 反例证明：旧请求在新目标保存后、服务启动命令到达前成功，原实现会把旧成功时间记给新目标；修复后不再污染。
- 初次启动、重新检查及系统服务重启统一读取已保存目标。测试拒绝了“旧 Intent 直接早退”的中间方案，该方案可能漏掉前台服务启动；最终不使用这个分支。
- 保留既有超时 watchdog、取消旧请求、迟到响应保护、通知品牌和投递规则；图片及消息事件流生产代码未改。
- 导航测试补齐初始历史状态、等待自动恢复后才验证点击恰好一次；未放宽既有断言或修改导航生产逻辑。
