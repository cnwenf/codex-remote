# 消息列表：保存、恢复与渲染约定

## 分工

- `src/protocol/thread-store.ts`：按 thread/turn/item ID 接收实时事件，维护单条正文与运行状态。
- `src/protocol/message-content.ts`：统一消息类型、正文提取，以及增量、桌面纯文本、完整正文的交接规则。
- `src/protocol/message-order.ts`：保留快照未覆盖的历史，校正共同消息的顺序，再按相邻已知消息插入缺项。
- `src/web/state/conversation-history.ts`：纯函数恢复历史、合并实时状态、确认乐观用户消息；不访问网络、不决定折叠。
- `src/web/state/use-codex.ts`：组织请求和订阅，限制快照轮询并发，防止过时快照结束新一轮运行。
- `src/gateway/desktop-state.ts`：有界读取 JSONL，新旧记录格式都能恢复正文，不读取整个大型会话文件。
- `src/gateway/active-message-replay.ts`：有界保留正在输出的原始正文，连接恢复时先发送完整前缀，再发送后续增量；完成历史仍由持久化快照负责。
- `src/web/components/timeline.tsx`：稳定渲染消息；仅工具和推理记录进入折叠区域。

## 不变量

1. 所有用户消息、助手中间说明和最终回复始终保留。完成状态不改变它们的容器，不按“最后一条”或 phase 隐藏其他正文。
2. 消息类型统一识别 camelCase、PascalCase、下划线与连字符写法。未知工具类型仍显示为活动记录。
3. 增量是增量，内容相同不代表重复事件。没有事件身份时，不能仅凭文本长度和相等判断去重。
4. 桌面 DOM 的 innerText 会丢失 Markdown。保留独立的增量和 DOM 观测，不把无法对齐的两种表示直接拼接。
5. 单条正文完成不必等整轮完成；完整快照要同时接管正文和完成标记，不能把未补全的残片冻结。
6. 完成正文不接受迟到的 start、delta、DOM 覆盖；仍可补入之前缺失的其他 item。turn/completed 携带的 items 同样参与恢复。
7. 历史尾页不删除已有项，也不把未覆盖的前文移到最终回复后；完整起点快照、乱序补回和向前翻页均有独立回归。
8. 正文不使用工具记录的 4,000 字摘要上限。文件读取仍受页大小和最大扫描范围限制。
9. 用户停在底部时跟随新输出、图片与可用视口大小变化；用户阅读历史或展开工具时不强行拉到底部。
10. 重连基线使用独立的 `gateway/agentMessageSnapshot`，不伪装成 start 或 delta。可替换缺前缀的残片与 DOM 文本，但不能缩短已有原始正文、覆盖完成正文或重新激活完成轮。
11. 实时恢复缓存最多 64 项、256K UTF-16 字符，仅从已观察到的 start 开始积累。未知或已淘汰正文的后续残片不能冒充完整前缀；结束标记阻止迟到事件重新开启缓存。网关自身中途重启或缓存淘汰后的正文，仍依赖持久化历史恢复。

## 回归入口

```sh
pnpm test src/web/state/message-pipeline.test.tsx
pnpm test src/gateway/desktop-state.test.ts
pnpm test src/gateway/active-message-replay.test.ts src/gateway/server.test.ts src/protocol/thread-store.test.ts
pnpm test src/web/components/conversation-viewport.test.tsx
pnpm check
pnpm e2e
```

重点场景：多工具之间的多段正文；中途追加用户消息；最终回复先到、中间项后补；终态 payload 补项；完成后迟到事件；下一轮运行期间的旧轮工具事件；有/无共享消息的历史合并；单条完成但整轮仍运行；DOM 与 Markdown 单片、双片、逐字符交接；长正文超过 4,000 字；大工具记录隔开的新旧 JSONL 尾页；移动端工具展开与图片延迟改变布局。

自动化协议夹具不等于真实 Desktop/Android 验收。发布与验收记录应分别报告自动化、真实历史页面、实时发送、原生客户端和实际安装版本，不把某一层通过解释成全链路完成。
