# 原生模拟器验收记录（2026-09-07）

## 结论

初次验收失败的选图、大图历史和随后发现的移动端 UI 缺口，均继续纳入同日修复。以下按轮次保留证据，较早章节中的“未修改”“未发版”只描述该轮状态，不代表最新结果。

## 0.5.27 候选包续验

### 本轮新增修复

- iPhone 可编辑控件最小字体为 16 px，避免聚焦自动放大；保留用户手动缩放。连接编辑页增加安全区和短屏滚动，键盘弹出时保存按钮仍可到达。
- 继续使用完整软件键盘发现原生 WebView 未缩小、输入区被遮挡，收起键盘又残留外层偏移。接入仅 iOS 启用的官方 Keyboard 8.0.5，采用 native resize、CSS 安全区和外层禁止滚动；未保留试验性的全局 `body:fixed` 补丁。配置依据[官方 Keyboard 文档](https://capacitorjs.com/docs/apis/keyboard)，通过原生点击验证，不把配置契约测试当成页面行为证明。
- 长标题下固定连接按钮的可见空间，不再被挤出移动端导航栏。
- 对话自动跟随仅在实际向上滚动时退出；图片加载引发的布局增长和滚动锚定不再误判为用户上翻。切换对话、历史前插和主动阅读位置分别回归。
- Android 通知权限不在拒绝、需说明或已申请的情况下反复弹出；首次申请前持久化标记，并合并并发申请。
- 默认 Android instrumentation 的应用 ID 修正；本次执行全部 4 项，而非只选择图片路由的 3 项。
- 大图历史预算改为单条记录 64 MiB、投影元数据 2 MiB、最多 8 次恢复、共享 256 MiB I/O 上限。78 MiB 的同轮两组大图夹无逐项身份文本也须完整恢复。预算耗尽明确报错，不推进游标、不给出错误的“历史完整”。
- 真实上游失败会保留错误正文并显示失败提示，不把“没有生成最终回复”伪装成空闲。历史正文仍读取有界本地记录，最近轮次的状态通过 Desktop 只读元数据恢复，不重新传输整段图片正文。

## 问题 A：系统相册图片在 WebView 读取阶段失败

复现步骤：

1. 在 Android 客户端展开输入区，点击添加图片。
2. 从系统 Photo Picker 的 Photos 页选择测试 PNG，完成选择。
3. 返回后附件名称变为系统生成的名称，缩略图损坏。
4. 点击发送，立即出现“图片读取失败”。

对照操作：同一张图片，通过 Photo Picker 右上角菜单的 Browse 进入文件浏览器选择，预览、上传、模型识图均成功。

已确认边界：失败发生在 `native-image-upload.ts` 的 FileReader 读取阶段，尚未进入文件分块写入及最终 HTTP 传输；连接绿色不能证明文件可读。具体是 URI 授权、系统选择器还是该 WebView 版本的兼容问题，仍需进一步定位，不能据此把所有失败归因于网络或 VPN。

## 问题 B：大图 JSONL 记录超过读取窗口，历史恢复漏掉用户消息

复现步骤：

1. 通过文件浏览器发送结构合法、大小精确为 10 MiB 的 PNG。
2. 确认发送成功，图片及最终回复在客户端可见。
3. 冷启动客户端，使用保存的连接，搜索并打开同一对话。
4. 最后一条用户图片消息消失，最终读图回复仍然可见。

进一步只读检查：

- 原始会话文件为 14,182,386 字节；大图的单条 JSONL 记录为 13,981,646 字节，记录本身仍存在。
- `desktop-state.ts` 按最多 2 MiB 的窗口读取，每个窗口从换行后对齐；未拼接跨窗口的超长 JSON 行，并有 8 MiB 的总扫描限制。
- 直接对**当前未发布源码**调用历史读取也能复现，不只是已安装旧网关的表现。
- 把全部 3 页取完，普通文本、两条重复文本和较早的 32 KB 用户图片能恢复，但最后的 10 MiB 用户图片消息始终未返回。

因此不能仅扩大首次加载轮数或修前端去重。需要修复历史读取对超长记录的处理，并增加大图、多图、分页和冷启动恢复回归；不能简单放弃读取上限。
